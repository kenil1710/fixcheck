## What held up

* **Leader forgery at filing.** The validator re-runs `gather()` and compares the whole evidence record by strict JSON equality. That covers every canonical field and the sha256 of every fetched body (report, docs, audited, fix, source, plus impl). A swapped deployed function is rejected (`T11 test_forged_leader_evidence_is_rejected`). At decide, validators recompute and must match verdict and basis. Quote indices are leader-chosen but must point at real substantive lines, as documented.
* **Model disagreement.** `combine_votes` returns FIXED/NOT_FIXED only when both answers agree and both are valid and grounded. A flip, invalid quote, ungrounded answer or error always gives INCONCLUSIVE. I found no path where a disagreement produces anything else. (Findings 5 and 6 are about what counts as *grounded*, not about disagreement.)
* **Comment and fence injection.** Comments are stripped before canonicalisation, prompt and storage, and a function inside a comment is not a function. Fences use a per-check nonce, and `<<<`/`>>>` and the nonce are removed from the data. Only string literals get through (finding 6).
* **Formatting.** Whitespace and comment changes still match. A one-character change does not match, `uint x` ≠ `uintx`, and Unicode look-alikes are not folded. Renamed locals go to the model, as documented.
* **Same name, same bundle.** Two different bodies under the audited basename, or two in one file, give `FUNCTION_OVERLOADED` → INCONCLUSIVE. Interface declarations are skipped.
* **Deadlines at both windows.** At 3600 s and at 90 s, `counter_stake` works at deadline−1 and is refused exactly at the deadline. `decide` is refused at deadline−1 and allowed exactly at the deadline. `decide` is refused at the decide deadline and `expire` is allowed exactly then, so there is no gap and no overlap. A second `decide`/`expire` raises with no writes. A late `counter_stake` is refused with the value left withdrawable. Defenders can't block `decide`, and `expire` is permissionless, so no stake can be trapped.
* **Ledger.** The invariant is asserted after every call in both suites, and it holds on chain. Canonical: 29 = 0 open + 28.84 withdrawable + 0.16 fees. Demo: 4 = 1 + 2.98 + 0.02.
* **Source fetch failures.** A transport error, non-200 or non-JSON response gives `SOURCE_UNREADABLE`, and a 404 gives `CONTRACT_NOT_VERIFIED`. Both are refusals with the stake withdrawable, never a verdict. A truncated or flattened source (Blockscout `main.sol`) gives at worst `FUNCTION_MISSING` → INCONCLUSIVE, never NOT_FIXED.
* **Seeds.** All 48 distinct evidence URLs in `docs/research/seeds.json` return 200. I re-ran `gather()` and the code decision against live Blockscout/Sourcify/GitHub data for all 22 seeds: 17 code verdicts are identical to chain and the 5 model cases still reach the model. Creation dates (Sourcify deployment info and chain block times) match RESEARCH §5: OP PrizePool/Vault/RngWitnet/DrawManager 2024-04-18, Base vault 2024-05-15, Arbitrum vault and RngWitnet 2024-05-29, Claimer OP/Base 2024-07-16, Ethereum vault 2024-08-19, Mellow 2025-09-08 (RedeemQueue 2026-01-23), Cap impl 2025-09-05, OP DisputeGameFactory impl 2026-05-07. Fix commit dates: 2024-06-28 → 2024-07-12. One observation, not a FixCheck error: the Arbitrum RngWitnet (created 2024-05-29) equals fix commit `e44b23c` (merged 2024-07-08), so those lines existed before the merge. RESEARCH §5 could say so.
* **Deployed code.** `tools/verify_source.mjs` read the code of all three addresses back from studio-dev. Each is byte-identical to HEAD (FixCheck and demo `107501bf…a030`, FixRegistry `dac4e78b…a541`), and FixRegistry's `source()` is the canonical address.
* **Frontend.** The live site listed only that deployment's addresses and commit `655d61e`, with no superseded address anywhere. Tallies, protocol scorecards and the ledger equal the chain reads, and all 35 external links on the main pages return 200. Cosmetic: demo check #10 is past its decide deadline and still shows "Being checked" until someone calls `expire`.
* **Registry history.** A decided key can be refiled and `latest_by_key` moves to the newest verdict, but every check stays readable via `get_checks`, so no history is lost.

## Interpretations (deliberate)

* **Fix 1, audited commit.** 6 of the 21 findings (PoolTogether M-14, M-19; Mellow H-1, H-5, M-1; Cap M-1) carry no code links in their own section. A Sherlock audit has one audited commit per repository, and the same pinned report links it in its other findings, so binding falls back to the report (`audit_binding = REPORT`, shown on the check page). Strict section-only binding would refuse those six; the fix commit is always bound to the finding's own section.
* **Fix 1, fix commit.** Sections link PRs, not merge commits. The PR's `.patch` (immutable for a merged PR) lists its commits without needing the rate-limited GitHub API; the fix file must be the PR's **head** commit. For all 22 seeds the function body at the PR head equals the merge commit's (checked before switching).
* **Fix 3.** Read as the three cases named (override, derived contract, library copy) plus same-name copies. Unrelated contracts that merely share a function name do not run in place of ours and are ignored: the vault bundle carries `PrizePool.claimPrize` (a contract the vault calls), and Cap's `Lender.liquidate` is the entry point that calls the audited library. A literal "any file" rule would have made those three checks INCONCLUSIVE for no reason. The full-match rule is applied to Blockscout as well as Sourcify.
* **Fix 6.** String literals are blanked in all *code* the model sees (deployed function and fix change). The finding text is the auditor's prose from the pinned report: it is fenced as untrusted data with a per-check nonce but not blanked, since blanking quotes in prose would garble it.
* **Live reads.** Creation records, the commit feed and the proxy slot carry mutable fields (balances, confirmations), so validators compare the extracted fields (creation tx, timestamp, commit date, implementation address) with strict equality rather than the bodies' sha256. Every immutable body (report, docs, audited, fix, PR patch, verified sources) is still compared by sha256.
